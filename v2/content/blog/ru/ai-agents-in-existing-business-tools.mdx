## Прямой ответ

Ставьте агентов **туда, где работа уже происходит**. Если intake живёт в email и CRM, агент должен читать и писать там - а не загонять каждого пользователя в новый portal. Новые платформы могут прийти позже; первая победа - убрать лишние hops.

## Default surfaces

- Inbox и calendar для communication work
- CRM для состояния pipeline
- Docs / wiki для knowledge
- Chat для внутренних ops-сигналов
- Sheets для lightweight queues, когда это и есть реальный system of record

## Integration pattern

1. Observe: какой tool - source of truth для каждого поля?
2. Act: какие writes - drafts, а какие live?
3. Gate: какие writes требуют human approval?
4. Notify: где человек видит очередь?
5. Log: где храним решения агента?

## Anti-patterns

- Строить параллельный «AI workspace», который никто не открывает
- Синхронизировать каждое поле в обе стороны в день один
- Позволять агенту изобретать CRM-стадии, которых нет в вашем процессе

## FAQ

### Нужна ли custom agent platform сразу?
Обычно нет. Начните с tools of record и тонкого orchestration layer.

### Что, если у tools нет API?
Начните с human-in-the-loop drafts и export/import, затем автоматизируйте connector с наивысшим ROI.
