## Прямой ответ

Browser и computer-use agents мощные и хрупкие. Используйте их для ограниченных internal tasks с recording, least privilege и human gates - не как unsupervised employees на production admin panels.

## Что это

Агенты, которые кликают UI или управляют desktop, когда APIs нет.

## Почему команды хотят их

Legacy portals, partner sites, нет бюджета на API.

## Риски

Кража credentials через page content, prompt injection из untrusted HTML, необратимые clicks, non-reproducible failures, audit gaps.

## Более безопасный pattern

Отдельный browser profile, vaulted credentials, allowlisted domains, step caps, human confirmation на submit/pay/delete, full session logs.

## Предпочитайте APIs когда возможно

API agents проще тестировать, scope'ить и rate-limit'ить, чем pixel-level automation.

## FAQ

### Browser agents production-ready?
Для узких, monitored paths - возможно. Для open-ended «делай мою работу» - нет.

### Могут ли они заменить RPA?
Иногда. RPA всё ещё может быть стабильнее на fixed UIs.
