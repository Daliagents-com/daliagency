## Ուղիղ պատասխան

Ամեն side-effecting tool-ին պետք է **idempotency key** և safe retry policy։ Դրեք agent work-ը queues-ի վրա, երբ volume-ը կամ flaky networks-ը կարևոր են։ Blind retries-ը ստեղծում են silent financial և CRM disasters։

## Ինչու agents-ը double-write են անում

Timeouts, user double-clicks, webhook redelivery, model retries mid-plan։

## Idempotency keys

Derive արեք business identity-ից (order id + action) կամ server-issued keys, որոնք պահվում են side effect-ից առաջ։

## Queues

Buffer արեք spikes, control արեք concurrency, isolate արեք poison messages։

## Webhook + agent

Verify արեք signatures, dedupe արեք delivery ids, process արեք exactly-once business layer-ում։

## Event-driven vs cron

Events immediacy-ի համար. cron reconciliation sweeps-ի համար - ոչ որպես միակ correctness mechanism։
