## Ուղիղ պատասխան

Մեծ ops գործակալներն աշխատում են, երբ օգտագործում են ադապտերներ խանութների և ապրանքների համար, գործում են իրական տվյալների վրա և մատյանագրում են յուրաքանչյուր փոփոխություն։ Շահումը՝ ավելի քիչ ձեռքով օպերատոր կրկնվող ապրանքային և զեղչային աշխատանքի վրա, պարտադիր ստուգմամբ անվտանգ չլինող գործողությունների վրա։

Մեկ «ունիվերսալ prompt բոլոր marketplace-ների համար» առանց ադապտերների և store id-ի արագ գրում է սխալ տեղում։

## Ի՞նչ է սա նշանակում գործնականում

- Սկսեք իրական աշխատանքային հոսքից. գներ, պաշարներ, նկարագրություններ, զեղչեր - ոչ թե մոդելի բրենդից։
- Նկարագրեք վարքը պարզ լեզվով, հետո ստուգեք ուղիները, որտեղ գործակալը փոխում է փողը, մուտքը կամ հրապարակային քարտերը։
- Թողեք մարդու ուղի ոչ ստանդարտի համար. վիճելի զեղչ, պաշարի կոնֆլիկտ, վիճելի SEO տեքստ։

## Ինչպիսին է լավը

- Հստակ store / brand / product id յուրաքանչյուր tool կանչի վրա։
- API ադապտերներ. մեկ ներքին պայմանագիր → տարբեր marketplace-ներ։
- Ստանդարտ / ոչ ստանդարտ երթուղավորում գրառումից առաջ։
- Մատյան. ով (գործակալ/մարդ), ինչ փոխվեց, old → new, երբ։
- Մարդու վերահսկման կետեր զանգվածային զեղչերի, ջնջման, շեմից ցածր գնի վրա։
- Կանգառի կոճակ և rollback մատյանով, որտեղ API-ն թույլ է տալիս։

## Ինչպիսին է վատը

- «Դեմո կատալոգի պրևյուում աշխատում է» առանց մարտական ծավալների։
- Ընդհանուր admin թոքեններ բոլոր խանութների վրա առանց scope-ի։
- Բացառությունների դեպքում մարդուն փոխանցում չկա։
- Փոփոխություններ առանց մատյանի. «ինչ-որ մեկը գիշերը գինը տեղափոխեց»։
- Խանութի կռահում չաթի տեքստից՝ հստակ id-ի փոխարեն։

## Օրական ծավալ և բեռնվածություն

Պլանավորեք batch պատուհաններ, հերթեր և API սահմանափակումներ։ Գործակալը, որը «ամեն ինչ միանգամից է թարմացնում» պիկին, սպանում է քվոտաները և թողնում մասնակի թարմացումներ։ Ավելի լավ է. task հերթ, իդեմպոտենտ թարմացումներ, միայն failed items-ի կրկնում։

## Մեկուսացում և multi-tenant

Եթե գործակալությունը վարում է ուրիշների խանութներ - տեսեք [հաճախորդների մեկուսացումը](/arm/blog/multi-tenant-isolation-for-agency-agents)։ Ուրիշի կատալոգը retrieval-ում = վստահության միջադեպ։

## FAQ

### Արդյո՞ք առանձին գործակալ է պետք յուրաքանչյուր խանութի համար։
Պարտադիր չէ առանձին runtime։ Պետք են առանձին credentials, store id և տվյալների սահմաններ։ Shared code + isolated config - նորմա է։

### Ի՞նչը պարտադիր է gate անել։
Զանգվածային զեղչեր, SKU ջնջում, գին նվազագույն մարժայից ցածր, վիճելի բովանդակության հրապարակում, մուտքի իրավունքների փոփոխություն։

### Արագ AI նախատիպն անպե՞տք է ops-ի համար։
Ոչ - հարմար է UI-ի և draft flow-ի համար։ Վտանգավոր է, եթե առանց ադապտերների, մատյանների և review-ի գնում է մարտական կատալոգ։
