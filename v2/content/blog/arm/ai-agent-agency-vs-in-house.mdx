## Ուղիղ պատասխան

Ընտրեք **AI agent գործակալություն**, երբ պետք են production համակարգեր իրական workflow-ների վրա արագ, engineering + operations կարգապահությամբ, և դեռ չունեք in-house agent ops կարողություն։ Կառուցեք **in-house**, երբ agent-ները product-ի միջուկն ու moat-ն են, կարող եք ապահովել մշտական ownership և արդեն ունեք հստակ process քարտեզներ և approve կանոններ։

Թիմերի մեծ մասը ձախողվում է այս երկու բևեռների միջև. վարձում են ֆրիլանսեր demo չաթբոտի համար կամ գործարկում ներքին «AI նախաձեռնություն» առանց workflow discovery-ի։ Production agent-ները ապրում են գործիքներում, որոնք թիմն արդեն օգտագործում է՝ inbox, CRM, sheets, chat, human gate-երով ռիսկային գործողությունների վրա։

## Որոշման չափորոշիչներ

| Չափորոշիչ | Գործակալություն | In-house |
| --- | --- | --- |
| Ժամանակ մինչև առաջին production path | Ավելի արագ, եթե discovery-ն ներառված է | Դանդաղ, մինչև hiring-ը և process-ները հասնեն |
| Գիտելիքի պահպանում | Ռիսկ, եթե ամբողջ կոնտեքստը վենդորի մոտ է | Ուժեղ, եթե թիմը փաստաթղթավորում է համակարգերը |
| Վերահսկում և approvals | Լավ, երբ gates-ը նախապես նախագծված են | Լավագույնը, երբ security-ն է տիրապետում stack-ին |
| Ծախսի ձև | Նախագիծ + ընտրովի retainer-ներ | Աշխատավարձեր + infra + management ծանրաբեռնվածություն |
| Տարբերակում | Լավագույնը ops leverage-ի համար, ոչ ունիկալ IP-ի | Լավագույնը, երբ agent-ները *հենց* product-ն են |
| Hiring-ի իրականություն | Agent ինժեներների hiring պետք չէ | Senior agent ինժեներները սակավ են և պահանջված |
| LLM ծախսերի ownership | Վենդորը գնահատում է, key-երը ձեզ մոտ են | Դուք եք տիրապետում բյուջեներին, cap-երին և օպտիմալացմանը |
| Evals և ռեգրեսիա | Պետք է գա pilot-ի հետ | Կարգապահությունը ինքներդ պետք է կառուցեք |
| Incident response | Սահմանված է retainer-ում կամ բացակայում է | Ձեր on-call ռոտացիան, ձեր pager-ը |

## Ինչ է իրականում արժենում ամեն ուղին

Ազնիվ համեմատությունը առաջին տարվա ամբողջ արժեքն է, ոչ pilot-ի invoice-ը աշխատավարձի տողի դիմաց։

**Գործակալության ուղի.** նախագծի վճար գումարած ընտրովի retainer գումարած LLM usage։ Տիպիկ շուկայական միջակայքեր. audit-ներ մոտ $2,000-15,000, մեկ workflow-ի pilot-ներ $10,000-50,000, ops retainer-ներ $1,500-10,000 ամսական։ Սրանք տիպիկ շուկայական միջակայքեր են, ոչ Dali-ի quote-եր։

**In-house ուղի.** աշխատավարձեր գումարած management ժամանակ գումարած ինֆրաստրուկտուրա գումարած LLM usage գումարած on-call։ Նվազագույն վստահելի թիմը մեկ senior ինժեներ է իրական agent փորձով գումարած product owner-ի մի մասնաբաժին։ Շուկաների մեծ մասում դա նշանակալի վեցանիշ տարեկան պարտավորություն է դեռ մոդելի ծախսերից առաջ։

**Երկու ուղիներում էլ.** LLM call costs-ը մշտական բյուջեի տող է, ոչ գործարկման միանվագ ծախս։ Գնահատեք մեկ workflow-ի համար իրական ծավալով, պահեք ձեր սեփական API key-երը և դրեք cap-եր, որ retry ցիկլը finance-ին անակնկալ չբերի։

## 12-ամսյա հայացքը

| Շրջան | Գործակալության ուղի | In-house ուղի |
| --- | --- | --- |
| Ամիսներ 1-3 | Audit, pilot, առաջին gated workflow-ը production-ում | Hiring, tool-երի ընտրություն, առաջին նախատիպեր |
| Ամիսներ 4-6 | Երկրորդ workflow, retainer ops, թիմի ուսուցում | Առաջին production path, եթե hiring-ը ստացվեց |
| Ամիսներ 7-12 | Handoff ներքին owner-ին, կամ կայուն retainer | Eval կարգապահություն, on-call ռոտացիա, roadmap |

Գործակալության ուղին գնում է արագություն և ռիսկը վաղ է փոխանցում։ In-house ուղին գնում է ownership, բայց դրա համար վճարում է օրացուցային ժամանակով և hiring ռիսկով։

## Երբ է գործակալությունը ճիշտ ընտրություն

- Պետք է **custom agent համակարգ** intake-ի, support-ի, ops-ի կամ knowledge աշխատանքի համար, ոչ սլայդներ։
- Ուզում եք agent-first product աշխատանք delivery ownership-ով։
- Պետք է օգնություն approve սահմանները սահմանելու հարցում, մինչ որևէ ինքնավար բան դուրս կգա։
- Զուգահեռ կարևոր է **AI տեսանելիությունը** (SEO/GEO), որ բիզնեսը գտնվի, մինչ համակարգերը կառուցվում են։

Dali-ն սրան մոտենում է որպես agent systems ստուդիա. նախ process discovery, հետո implementation ուղիներ, որոնք տեղավորվում են առկա գործիքներում։ Տես [solutions](/arm/solutions) և [սկսեք audit-ով](/arm)։

## Երբ է in-house-ը ճիշտ ընտրություն

- Agent-ները այն product-ն են, որի համար հաճախորդները վճարում են, և roadmap-ը բազմամյա է։
- Արդեն ունեք platform eng, evals և on-call ավտոմատացման համար։
- Compliance-ը պահանջում է, որ ամբողջ լոգիկան և data residency-ն մնան միայն ձեր կազմակերպությունում։

Նույնիսկ այդ դեպքում կարճ agency sprint-երը discovery-ի կամ ճարտարապետության review-ի համար նվազեցնում են թանկ rework-ը։

## Հիբրիդային ուղին, որը մեծամասնությունը պետք է դիտարկի

Միջին չափի ընկերությունների մեծ մասի համար ամենաուժեղ պատերնը հաջորդական է, ոչ «կամ-կամ».

1. Գործակալությունը վարում է discovery-ն և առաջին gated workflow-ը հասցնում production։
2. Ձեր թիմը այն օպերացնում է սահմանված աջակցության պատուհանում, գործակալությունը on-call է։
3. Ներքին owner-ը ստանձնում է runbook-ը, eval set-ը և gate կանոնները։
4. Գործակալությունը անցնում է advisory-ի, կամ կառուցում է հաջորդ workflow-ը, մինչ ձեր owner-ը վարում է առաջինը։

Գրեք exit չափորոշիչները առաջին պայմանագրում. որ արտեֆակտներն են փոխանցվում, ով է ուսուցանվում և երբ կարող է retainer-ը ավարտվել առանց տուգանքի։ Վենդորը, որը դիմադրում է սահմանված exit չափորոշիչներին, վաճառում է կախվածություն, ոչ կարողություն։

## Ձախողման ռեժիմներ (երկու կողմերում)

**Գործակալության ուղին ձախողվում է, երբ** engagement-ը բաց է թողնում workflow mapping-ը, հասցնում է chat UI առանց tool integrations-ի կամ երբեք չի սահմանում, թե ով է հաստատում անշրջելի գործողությունները։ Այն ձախողվում է նաև լուռ, երբ վենդորն է պահում ամբողջ կոնտեքստը և ամեն փոփոխություն դառնում է ticket։

**In-house ուղին ձախողվում է, երբ** ղեկավարությունը ֆինանսավորում է մոդելներն ու prompt-ները, բայց ոչ ownership-ը, evals-ը և change management-ը։ Tool sprawl-ն աճում է. pilot-ից հետո agent-ին ոչ ոք չի պահպանում. միակ ինժեները, որը հասկանում էր համակարգը, հեռանում է։

## Գործնական հաջորդականություն

1. Քարտեզագրեք 3-5 բարձր ծավալի workflow և դրանց ձախողման արժեքը։
2. Նշեք, թե որ քայլերին է պետք human gate։
3. Ընտրեք մեկ ուղի դեպի production առկա գործիքներում։
4. 2-4 շաբաթ չափեք cycle time-ը և սխալների մակարդակը։
5. Միայն հետո ընդլայնվեք կամ վարձեք մշտական agent թիմ։

Dali-ն միավորում է engineering-ը և operations-ը. custom agent համակարգեր, agent-first product-ներ, consulting և AI տեսանելիության համակարգեր։ Հրապարակային աշխատանքներ՝ [Kora](/arm/project/kora) և [agents.ge](/arm/project/agentsge)։ Եթե ուզում եք հիմնավորված audit, թե որտեղ են agent-ները տեղին ձեր stack-ում, օգտագործեք կայքի CTA-ն անվճար խորհրդատվության համար։

## FAQ

### AI agent գործակալությունը նույնն է՞, ինչ չաթբոտի վենդորը։
Ոչ։ Չաթբոտները պատասխանում են հարցերին։ Production agent համակարգերը կատարում են բազմաքայլ աշխատանք tools-ով, կանոններով և human review-ով։

### Կարո՞ղ ենք սկսել ֆրիլանսերներով։
Այո՝ նեղ script-ների համար։ Multi-tool ops-ի համար approvals-ով պետք է product և process ownership՝ գործակալություն կամ in-house senior կարողություն։

### Ի՞նչ անել GEO-ի և SEO-ի հետ, մինչ agent-ներ ենք կառուցում։
Տեսանելիությունը զուգահեռ համակարգ է։ Content-ը և entity ազդանշանները չեն փոխարինում product աշխատանքին, բայց որոշում են, թե ճիշտ գնորդները ձեզ կգտնե՞ն։

### Ո՞վ պետք է վճարի LLM API հաշիվը։
Երկու ուղիներում էլ պահեք ձեր սեփական API key-երը։ Վենդորները պետք է տան usage գնահատականներ և cap-եր մեկ workflow-ի համար. անթափանց վենդորի billing-ը դժվարացնում է և՛ ծախսերը, և՛ վենդորի փոխարինումը։

### Որքա՞ն մեծ պետք է լինենք in-house գնալու համար։
Headcount-ը սխալ trigger է։ Իրական trigger-ը կայուն ownership-ն է. senior մարդ, որի իրական աշխատանքը agent-ներն են, գումարած eval և on-call կարգապահություն։ Առանց դրա in-house-ը նշանակում է չպահպանվող pilot։
