## Ուղիղ պատասխան

Դրեք գործակալներին **այնտեղ, որտեղ աշխատանքն արդեն տեղի է ունենում**։ Եթե intake-ը ապրում է email-ում և CRM-ում, գործակալը պետք է կարդա և գրի այնտեղ - ոչ թե ստիպի յուրաքանչյուր օգտատիրոջ մտնել նոր portal։ Նոր platform-ները կարող են գալ ավելի ուշ. առաջին հաղթանակը hop-երը հանելն է։

## Default մակերեսներ

- Inbox և calendar՝ communication աշխատանքի համար
- CRM՝ pipeline state-ի համար
- Docs / wiki՝ knowledge-ի համար
- Chat՝ ներքին ops signal-ների համար
- Sheets՝ lightweight queue-երի համար, երբ դա իրական system of record-ն է

## Integration pattern

1. Observe. որ tool-ն է source of truth յուրաքանչյուր field-ի համար։
2. Act. որ write-երն են draft, որոնք՝ live։
3. Gate. որ write-երն են human approval պահանջում։
4. Notify. որտե՞ղ է human-ը տեսնում queue-ն։
5. Log. որտե՞ղ ենք պահում agent որոշումները։

## Anti-pattern-ներ

- Կառուցել զուգահեռ «AI workspace», որ ոչ ոք չի բացում
- Day one-ից ամեն field-ը երկու ուղղությամբ sync անել
- Թույլ տալ, որ գործակալը հորինի CRM stage-եր, որոնք ձեր պրոցեսում չկան

## Dali-ի bias

Մենք implement ենք անում production գործակալներ այն tools-ում, որոնք թիմերն արդեն վարում են։ Տես [լուծումների քարտեզը](/arm/solutions) multi-agent production pattern-ների համար։
