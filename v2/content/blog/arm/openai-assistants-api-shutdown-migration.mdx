## Ուղիղ պատասխան

2026-ի օգոստոսի 26-ին OpenAI-ն անջատում է Assistants API-ն՝ `/v1/assistants`, `/v1/threads` և `/v1/runs`։ Այդ ամսաթվից հետո այդ հարցումները վերադարձնում են սխալներ։ Դրանց վրա կառուցված հավելվածները չեն դեգրադացվում - նրանք ուղղակի դադարում են պատասխանել։ Փոխարինումը Responses API-ն է, և միգրացիան իրական ինժեներական աշխատանք է, ոչ թե URL-ի փոփոխություն։ Ռեալիստական ծավալը production բոտի համար՝ 1-2 շաբաթ։

## Ինչ կլինի ուղիղ օգոստոսի 26-ին

- `/v1/assistants`, `/v1/threads` և `/v1/runs`-ի ամեն կանչ սկսում է սխալներ վերադարձնել։
- Ոչ read-only, ոչ դեգրադացված ռեժիմ չկա։ Բոտը, որ ամեն զրույցի համար thread է ստեղծում, ընկնում է առաջին իսկ հաղորդագրության վրա։
- OpenAI-ն հայտարարել է deprecation-ը՝ Responses API-ի միգրացիայի ուղով։ Պաշտոնական migration փաստաթուղթը՝ [developers.openai.com/api/docs/assistants/migration](https://developers.openai.com/api/docs/assistants/migration)։
- Azure OpenAI Assistants-ը դուրս է գալիս նույն պատուհանում, այնպես որ տուժած լսարանը կրկնապատկվում է. Azure-ի վրա գտնվող թիմերը բացառություն չեն։

## Ինչու սա endpoint-ի փոխարինում չէ

Responses API-ն այլ ձև ունի, ոչ միայն այլ URL․

- Thread-ները և run-ի state-ը մինչ այժմ OpenAI-ն էր պահում իր կողմում։ Responses API-ում զրույցի state-ը ձեր հավելվածի գործն է՝ պահել պատմությունը, որոշել, թե ինչ է մտնում ամեն հարցման մեջ, կտրել context-ը։
- Փոխվում է արժեքի մոդելը։ Վճարում եք այն context-ի համար, որը նորից եք ուղարկում, ուստի միամիտ պորտը՝ "ամեն քայլին կրկնել ամբողջ thread-ը", արագ թանկանում է։
- Assistants-ի որոշ ֆիչրներ ուղիղ համարժեք չունեն - այդ ուղիները պետք է վերանախագծել, ոչ թե թարգմանել։
- Production հավելվածները, որոնք assistants դինամիկ են ստեղծում (ամեն tenant-ի, հաճախորդի, workflow-ի համար), մաքուր համարժեք չունեն։ Այդ ճարտարապետությունը պետք է վերաիմաստավորել։

## Ինչ կկոտրվի գործնականում

Տիպիկ զոհերը 2023-2025-ին այն ժամանակվա խորհուրդ տրվող stack-ի վրա հավաքված համակարգերն են․

- Support բոտեր՝ ամեն օգտատիրոջ համար thread-ով
- Intake և որակավորման բոտեր կայքերում
- Ներքին ասիստենտներ ընկերության փաստաթղթերի ու գործիքների վրա

Ամեն ակտիվ զրույց կընկնի հենց առաջին օրը։ Օգտատերերը տեսնում են մեռած widget, support-ը՝ դիմումների աճ, և ոչ ոք նախապես զգուշացնող banner չի տեսնում։

## Միգրացիայի չեկլիստ

1. **Մապել բոլոր կանչերը։** Ինվենտարիզացիա ամեն տեղի, որտեղ կոդը դիպչում է `/v1/assistants`, `/v1/threads`, `/v1/runs`-ին, և որ ֆիչրներից է կախված (file search, code interpreter, function calls, per-tenant assistants)։
2. **Պորտ Responses API-ի։** State-ի կառավարումը տեղափոխել հավելված, վերակառուցել tool-երի կապակցումը, ընտրել context-ի ռազմավարություն, որի դեպքում արժեքը խելամիտ է մնում։
3. **Eval-ները կողք կողքի։** Նույն մուտքերը հին ու նոր ուղիներով, արդյունքների համեմատում ցանկացած փոխարկումից առաջ։ Կապված՝ [ինչպես գնահատել ագենտներին go-live-ից առաջ](/arm/blog/how-to-evaluate-ai-agents-before-go-live)։
4. **Zero-downtime cutover։** Տրաֆիկի մի մասն ուղղել նոր ուղով, հետևել, հետո ամբողջությամբ փոխարկվել՝ պատրաստ rollback-ով։

Ռեալիստական ծավալը production բոտի համար՝ 1-2 շաբաթ։ Ավելի քիչ, եթե բոտը բարակ է; ավելի շատ, եթե per-tenant assistants եք կառուցել։

## Ինչ անել մինչև օգոստոսի 26-ը՝ նույնիսկ առանց մեզ

- Սառեցրեք փոփոխությունները այն flow-երում, որոնք դիպչում են Assistants API-ին։ Ամեն նոր ֆիչր հին stack-ի վրա միգրացիայի պարտք է։
- Thread-երի տվյալները արտահանեք հիմա։ Thread-երի պատմությունն անջատումից հետո վերականգնելի չէ։ Եթե զրույցները կարևոր են բիզնեսի համար (support-ի context, վաճառքի պատմություն, compliance)՝ վերցրեք դրանք, քանի դեռ endpoint-ները պատասխանում են։

## Ինչպես է Dali-ն սա վարում

Dali-ն Assistants API ծանրաբեռնվածությունները Responses API-ի է միգրացնում 1-2 շաբաթում, ֆիքսված գին՝ $1,900-ից․ կանչերի մապինգ, պորտ, eval-ներ միգրացիայից առաջ/հետո և zero-downtime cutover։ Երաշխիք․ եթե ընդունման թեստը չի անցնում՝ չեք վճարում։ Սկսեք աուդիտից՝ [solutions](/arm/solutions)։ Կապված՝ [production AI ագենտներ](/arm/blog/production-ai-agents-for-business), [ֆրեյմվորքներ և hosted assistants](/arm/blog/open-frameworks-and-assistants-when-to-use)։

## FAQ

### Իմ բոտն իրո՞ք կկանգնի։
Այո, եթե այն կանչում է `/v1/assistants`, `/v1/threads` կամ `/v1/runs`։ 2026-ի օգոստոսի 26-ից հետո այդ հարցումները սխալներ են վերադարձնում, ուստի ամեն զրույց ընկնում է։ Սա անջատում է, ոչ թե դանդաղում։

### Կարո՞ղ եմ ուղղակի endpoint-ները փոխել։
Ոչ։ Responses API-ն ձեր փոխարեն thread-ներ ու run-ի state չի պահում, context-ը այլ կերպ է գնագոյացնում, և որոշ ֆիչրներ ուղիղ համարժեք չունեն։ Փոխվում են client կոդը, state-ի պահեստավորումը և արժեքի պրոֆիլը։

### Ի՞նչ կլինի Azure OpenAI Assistants-ի հետ։
Azure-ն իր Assistants API-ն հանում է նույն պատուհանում։ Azure-ի վրա լինելը ժամանակ չի տալիս - նույն միգրացիան է պետք։

### Ի՞նչ արժե միգրացիան։
Սեփական ուժերով՝ մոտ 1-2 շաբաթ ինժեների, ով երկու API-ն էլ գիտի, գումարած eval-ներ ու cutover։ Dali-ի հետ՝ ֆիքսված գին $1,900-ից, ներառյալ eval-ները միգրացիայից առաջ/հետո և zero-downtime cutover-ը; եթե ընդունման թեստը չի անցնում՝ չեք վճարում։
