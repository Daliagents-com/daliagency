## პირდაპირი პასუხი

2026 წლის 26 აგვისტოს OpenAI თიშავს Assistants API-ს: `/v1/assistants`, `/v1/threads` და `/v1/runs`. ამ თარიღის შემდეგ ეს მოთხოვნები აბრუნებენ შეცდომებს. მათზე აგებული აპლიკაციები არ დეგრადირდებიან - ისინი უბრალოდ წყვეტენ პასუხს. ჩანაცვლება არის Responses API, და მიგრაცია რეალური საინჟინრო სამუშაოა და არა URL-ის შეცვლა. რეალისტური მოცულობა production ბოტისთვის: 1-2 კვირა.

## რა მოხდება ზუსტად 26 აგვისტოს

- ყოველი გამოძახება `/v1/assistants`, `/v1/threads` და `/v1/runs`-ზე იწყებს შეცდომების დაბრუნებას.
- არ არსებობს არც read-only და არც დეგრადირებული რეჟიმი. ბოტი, რომელიც ყოველ საუბარზე thread-ს ქმნის, პირველივე შეტყობინებაზე ვარდება.
- OpenAI-მ deprecation გამოაცხადა Responses API-ზე მიგრაციის გზით. ოფიციალური migration დოკუმენტი: [developers.openai.com/api/docs/assistants/migration](https://developers.openai.com/api/docs/assistants/migration).
- Azure OpenAI Assistants იმავე ფანჯარაში გადის, ასე რომ დაზარალებული აუდიტორია ორმაგდება: Azure-ზე მყოფი გუნდები გამონაკლისი არ არიან.

## რატომ არ არის ეს endpoint-ის შეცვლა

Responses API-ს სხვა ფორმა აქვს და არა უბრალოდ სხვა URL:

- Thread-ებს და run-ის მდგომარეობას აქამდე OpenAI ინახავდა თავის მხარეს. Responses API-ში საუბრის მდგომარეობა თქვენი აპლიკაციის საქმეა: ისტორიის შენახვა, გადაწყვეტა, რა შედის ყოველ მოთხოვნაში, კონტექსტის შეკვეცა.
- იცვლება ღირებულების მოდელი. იხდით იმ კონტექსტში, რომელსაც ხელახლა აგზავნით, ამიტომ გულუბრყვილო პორტი "მთელი thread-ის ყოველ ჯერზე გამეორება" სწრაფად ძვირდება.
- Assistants-ის ზოგ ფუნქციას პირდაპირი ეკვივალენტი არ აქვს - ეს გზები საჭიროებს გადაპროექტებას და არა თარგმნას.
- Production აპლიკაციებს, რომლებიც assistants-ებს დინამიურად ქმნიან (თითო tenant-ზე, კლიენტზე, workflow-ზე), სუფთა ეკვივალენტი არ აქვთ. ეს არქიტექტურა თავიდან უნდა გაიაზროთ.

## რა გატყდება პრაქტიკაში

ტიპური მსხვერპლი არის 2023-2025 წლებში მაშინდელ რეკომენდებულ სტეკზე აგებული სისტემები:

- Support ბოტები, რომლებიც თითო მომხმარებელზე thread-ს ინახავენ
- Intake და კვალიფიკაციის ბოტები საიტებზე
- შიდა ასისტენტები კომპანიის დოკუმენტებსა და ინსტრუმენტებზე

ყოველი აქტიური საუბარი პირველივე დღეს ჩავარდება. მომხმარებლები ხედავენ მკვდარ ვიჯეტს, support ხედავს მიმართვების ზრდას, და წინასწარ გამაფრთხილებელ ბანერს ვერავინ ხედავს.

## მიგრაციის ჩეკლისტი

1. **ყველა გამოძახების დამაპვა.** ინვენტარიზაცია ყოველი ადგილის, სადაც კოდი ეხება `/v1/assistants`, `/v1/threads`, `/v1/runs`-ს, და რომელ ფუნქციებზეა დამოკიდებული (file search, code interpreter, function calls, per-tenant assistants).
2. **პორტი Responses API-ზე.** მდგომარეობის მართვის აპლიკაციაში გადატანა, tool-ების ხელახლა აწყობა, კონტექსტის სტრატეგიის შერჩევა, რომ ღირებულება გონივრული დარჩეს.
3. **Eval-ების პარალელურად გაშვება.** ერთი და იგივე შეყვანები ძველ და ახალ გზაზე, შედეგების შედარება ნებისმიერ გადართვამდე. დაკავშირებული: [როგორ შევაფასოთ აგენტები go-live-მდე](/ge/blog/how-to-evaluate-ai-agents-before-go-live).
4. **Zero-downtime cutover.** ტრაფიკის ნაწილის ახალ გზაზე გადამისამართება, დაკვირვება, შემდეგ სრული გადართვა მზა rollback-ით.

რეალისტური მოცულობა production ბოტისთვის: 1-2 კვირა. ნაკლები, თუ ბოტი თხელია; მეტი, თუ per-tenant assistants ააგეთ.

## რა გავაკეთოთ 26 აგვისტომდე ჩვენს გარეშეც

- გაყინეთ ცვლილებები იმ flow-ებზე, რომლებიც Assistants API-ს ეხებიან. ყოველი ახალი ფუნქცია ძველ სტეკზე მიგრაციის ვალია.
- Thread-ების მონაცემები ახლავე გაიტანეთ. Thread-ების ისტორია გათიშვის შემდეგ აღდგენადი აღარ არის. თუ საუბრები ბიზნესისთვის მნიშვნელოვანია (support-ის კონტექსტი, გაყიდვების ისტორია, compliance) - წაიღეთ ისინი, სანამ endpoint-ები ჯერ კიდევ პასუხობენ.

## FAQ

### ჩემი ბოტი მართლა გაჩერდება?
დიახ, თუ ის იძახებს `/v1/assistants`, `/v1/threads` ან `/v1/runs`-ს. 2026 წლის 26 აგვისტოს შემდეგ ეს მოთხოვნები აბრუნებენ შეცდომებს, ამიტომ ყოველი საუბარი ვარდება. ეს გათიშვაა და არა შენელება.

### შემიძლია უბრალოდ endpoint-ები შევცვალო?
არა. Responses API თქვენ მაგივრად არ ინახავს thread-ებს და run-ის მდგომარეობას, კონტექსტს სხვანაირად ატარიფებს, და ზოგ ფუნქციას პირდაპირი ეკვივალენტი არ აქვს. იცვლება კლიენტის კოდი, მდგომარეობის შენახვა და ღირებულების პროფილი.

### რა ხდება Azure OpenAI Assistants-თან?
Azure თავის Assistants API-ს იმავე ფანჯარაში იღებს. Azure-ზე ყოფნა დროს არ გმატებთ - იგივე მიგრაცია გჭირდებათ.

### რა ღირს მიგრაცია?
საკუთარი ძალებით: დაახლოებით 1-2 კვირა ინჟინრისა, რომელმაც ორივე API იცის, პლუს eval-ები და cutover. Dali-სთან: ფიქსირებული ფასი $1,900-დან, eval-ებით მიგრაციამდე/შემდეგ და zero-downtime cutover-ით; თუ მიმღები ტესტი არ გადის - არ იხდით.
