## პირდაპირი პასუხი

გაასწორეთ (patch), როცა სტრუქტურა ჯანსაღია და პრობლემები ლოკალურია. თავიდან ააშენეთ კრიტიკული გზა, როცა auth, გადახდები ან multi-tenant მონაცემები გადახლართულია გენერირებულ სპაგეტთან. მარკეტინგის გვერდები დატოვეთ, თუ სტაბილურია.

სრული rewrite «რადგან AI წერდა» - ძვირი ჩვევა. პატჩი «გადახდის ხვრელზე ზემოდან» - ყალბი ეკონომია.

## რას ნიშნავს ეს პრაქტიკაში

- დაიწყეთ რეალური პროცესის რუკით: შესვლა, მონაცემები, ფული, წვდომები, გამავალი.
- აღწერეთ ქცევა მარტივი ენით, შემდეგ შეამოწმეთ ყველა გზა, სადაც შეცდომა ფულს ან რეპუტაციას ღირს.
- დატოვეთ ადამიანი არასტანდარტზე; ნუ გაასწორებთ «კიდევ ერთი პრომპტით» იმას, რაც ინჟინერიაა.

## როდის პატჩი

- UI და layout კარგია, ბაგები ერთ მოდულშია.
- საიდუმლო გასაღებები სერვერზე გადადის ერთი საზღვრით.
- ემატება rate limits, webhook signature, ერთი middleware.
- ტესტები შეიძლება დაკიდდეს ვიწრო გზაზე ხის მოჭრის გარეშე.

## როდის rewrite კრიტიკულ გზაზე

- Auth, payments, multi-tenant და tool გამოძახებები ერთ ფაილში/პრომპტშია გადახლართული.
- არ არის ნათელი order მოდელი, tenant id, server price.
- ყოველი ფიქსი მეზობელ ნაკადს არღვევს.
- არ არის ლოგები, მფლობელი, აგენტის/checkout-ის გაჩერების გზა.

## როგორ გამოიყურება კარგი

- მკაფიო საზღვარი: marketing shell vs hardened core.
- სტანდარტი / არასტანდარტი მარშრუტები ჩაწერამდე.
- გასაღებები მხოლოდ სერვერზე; ლოგები და გაჩერების ღილაკი.
- rewrite/patch გადაწყვეტილება წერილობითია «მზადაა» კრიტერიუმებით.

## როგორ გამოიყურება ცუდი

- «პრევიუში მუშაობს» = ship.
- ტოკენები და webhook საჯაროა «ჯერჯერობით».
- გამონაკლისებზე ადამიანთან გადაცემა არ არის.
- სრული rewrite პერფექციონიზმისთვის, სანამ funnel გადახდას არ იღებს.

## FAQ

### სწრაფი AI პროტოტიპი უსარგებლოა?
არა. ეს სწრაფი ზედაპირია. საშიშია მზა რეალურ ექსპლუატაციად მიჩნევა.

### ყველაფერს თავიდან წერთ?
არა ყოველთვის. ხშირად hardening. ზოგჯერ იზოლაცია და თავიდან აგება მხოლოდ auth/payments/tenant-ზე. მარკეტინგი რჩება, თუ სტაბილურია.

### როგორ სწრაფად გადავწყვიტოთ rewrite vs patch?
ერთი აუდიტით: შეიძლება თუ არა 1–2 სპრინტში ფული/წვდომა/იზოლაცია წერტილოვნად დაიხუროს? თუ არა - rewrite core, არა მთელი საიტი.
