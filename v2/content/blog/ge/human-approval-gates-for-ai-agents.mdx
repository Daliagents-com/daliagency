## პირდაპირი პასუხი

**Human approval gate** დადეთ ნებისმიერ agent მოქმედებამდე, რომელიც ძნელად შესაქცევია, მაღალი ფასი აქვს შეცდომაზე, ან გარედან ჩანს review-ის გარეშე. არ გეითოთ სუფთა research ნაბიჯები, რომლებიც მხოლოდ შიდა ჩანაწერებს ამზადებს.

Gate-ები ბიუროკრატია არ არის. ისინი საზღვარია სასარგებლო ავტომატიზაციასა და ოპერაციულ რისკს შორის.

## რა უნდა გეითდეს

- გაგზავნები: email, შეტყობინებები, ინვოისები, კონტრაქტის ცვლილებები
- ჩაწერები: CRM stage გადატანები, refund-ები, permission ცვლილებები
- ფული და წვდომა: გადახდები, admin როლები, production deploy-ები
- საჯარო კონტენტი: პოსტები, კლიენტისადმი პასუხები მგრძნობიარე თემებზე

## რა არ უნდა გეითდეს

- შიდა შეჯამებები ადამიანისთვის, რომელიც შემდეგ ნაბიჯს უკვე ფლობს
- Retrieval და ranking, რომელიც მხოლოდ მოგვიანებით დამტკიცებულ მოქმედებას აცნობს
- Draft generation, რომელსაც sandbox-იდან გასვლა approval-ის გარეშე არ შეუძლია

## მინიმალური gate დიზაინი

1. დაასახელეთ მოქმედება და მისი blast radius.
2. განსაზღვრეთ ვინ ამტკიცებს (role, და არა "ვინც ონლაინაა").
3. აჩვენეთ agent-ის evidence pack: inputs, განზრახული მოქმედება, confidence, წყაროები.
4. დაალოგეთ approve / reject / edit მიზეზით.
5. დროებით შეზღუდეთ stale approval-ები, რომ სამუშაო ჩუმად არ გაფუჭდეს.

## წარუმატებლობის რეჟიმები

- ყველაფრის გეითვა → აგენტები ნელ chat stub-ებად იქცევიან
- არაფრის გეითვა → ერთი ცუდი tool call კლიენტის ინციდენტს ქმნის
- ბუნდოვანი approver-ები → გადაწყვეტილებას არავინ ფლობს
- audit trail-ის გარეშე → policy-ის გაუმჯობესება შეუძლებელია

## როგორ იყენებს Dali gate-ებს

Production agent სისტემებში ჯერ workflow-ებს ვმაპავთ, შემდეგ gate-ებს შეუქცევად ნაბიჯებზე ვდებთ, შემდეგ დანარჩენს არსებულ tools-ში ვაავტომატიზებთ. დაიწყეთ [აუდიტით](/ge/solutions).

## FAQ

### ყველა agent შეტყობინებას approval სჭირდება?
არა. დაამტკიცეთ outbound და irreversible მოქმედებები, არა ყოველი შიდა draft.

### ვინ უნდა იყოს approver?
იგივე role, რომელიც უკვე ფლობს ამ გადაწყვეტილებას non-agent პროცესში.

### მოგვიანებით შეგვიძლია low risk auto-approve?
დიახ - მას შემდეგ, რაც გექნებათ logs, error rates და ნათელი risk score.
