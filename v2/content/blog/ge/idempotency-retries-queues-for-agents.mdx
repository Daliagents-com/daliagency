## პირდაპირი პასუხი

ყოველ side-effecting tool-ს სჭირდება **idempotency key** და safe retry policy. ჩადეთ agent work queues-ზე, როცა volume ან flaky networks მნიშვნელოვანია. Blind retries ქმნის silent financial და CRM disasters-ს.

## რატომ double-write-ავენ აგენტები

Timeouts, user double-clicks, webhook redelivery, model retries mid-plan.

## Idempotency keys

გამოიყვანეთ business identity-დან (order id + action) ან server-issued keys, რომლებიც side effect-მდე ინახება.

## Queues

Buffer spikes, control concurrency, isolate poison messages.

## Webhook + agent

Verify signatures, dedupe delivery ids, process exactly-once business layer-ზე.

## Event-driven vs cron

Events immediacy-ისთვის; cron reconciliation sweeps-ისთვის - არა როგორც ერთადერთი correctness mechanism.
