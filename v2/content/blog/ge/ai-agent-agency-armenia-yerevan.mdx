## პირდაპირი პასუხი

სომხეთში (ერევანი) AI agent პარტნიორის დაქირავება იმავე production checklist-ს მიჰყვება, რასაც დაქირავება ნებისმიერ სხვაგან: ერთი scoped workflow pilot, human gates რისკიან მოქმედებებზე, security საფუძვლები, evals და მკაფიო handoff. ერევნისთვის სპეციფიკური შრე fit-ს ეხება და არა განსხვავებულ სტანდარტებს: დაადასტურეთ time-zone overlap (სომხეთი მთელი წელი UTC+4-ზეა), თითოეული delivery artifact-ის ენა, საკონტრაქტო entity და ის, რომ გუნდის საინჟინრო სიღრმე ოპერაციულ დისციპლინამდეც აღწევს, რადგან agent-ები, რომლებიც თქვენს tools-ში მოქმედებენ, ops-ზე ვარდებიან და არა ალგორითმებზე.

## რას გაძლევთ ერევნის ბაზარი

სომხეთს რეგიონის ერთ-ერთი ყველაზე ღრმა საინჟინრო ტრადიცია აქვს: ძლიერი საუნივერსიტეტო pipeline-ები მათემატიკასა და CS-ში, ჩამოყალიბებული IT სექტორი, სადაც გლობალური კომპანიები ერევანში საინჟინრო ოფისებს ამუშავებენ, და სახელმწიფოს მხარდაჭერილი სტიმულები, რომლებმაც ინდუსტრიის ზრდა შეინარჩუნეს. მყიდველისთვის ეს ნიშნავს ნამდვილ senior საინჟინრო შესაძლებლობებს დასავლურ ბაზრებზე დაბალ განაკვეთებში.

დათქმა აგენტებისთვის სპეციფიკურია. კლასიკური software სიძლიერე ავტომატურად არ მოიცავს ოპერაციულ ჩვევებს, რომლებიც agent-ებს სჭირდებათ: approval gates, eval set-ები, tracing, ინციდენტების გზები. ბევრ ძლიერ ერევნულ გუნდს ისინი აქვს; გადაამოწმეთ და ნუ ივარაუდებთ, ზუსტად ისე, როგორც ბერლინში ან ოსტინში მოიქცეოდით.

## ძლიერი სიგნალები

- **კონკრეტული pilot-ები.** ერთი workflow, წერილობითი scope, acceptance test-ები, შეთანხმებული build-ამდე. არა platform pitch.
- **Integration გულახდილობა.** გეუბნებიან, თქვენს რომელ tools-ში შეუძლიათ მოქმედება, რომელში ვერ, და როგორ იქნება auth scoped. "ჩვენ ყველაფერთან ვინტეგრირდებით" red flag-ია და არა feature.
- **Security ჰიგიენა.** Secrets management, least-privilege credentials და პირდაპირი პასუხი იმაზე, სად ცხოვრობს logs და traces.
- **გადამოწმებადი references.** დასახელებული process artifact-ები - გასუფთავებული discovery output, gate map, eval სტრუქტურა - გადაუმოწმებელი მეტრიკების ნაცვლად. Reference, რომელსაც შეუძლია აღწეროს, როგორ მუშავდებოდა ინციდენტები, ლოგოების კედელს ჯობია.
- **Ops დისციპლინა.** მათ მხარეს ვიღაც ფლობს ხარისხს go-live-ის შემდეგ, და შეუძლიათ აღწერონ review queue და stop switch.

## თანამშრომლობის ლოგისტიკა

სომხეთი UTC+4-ზე მუშაობს daylight saving გადაწევების გარეშე, იმავე საათზე, რომელზეც საქართველო და Gulf.

| თქვენი გუნდი | სხვაობა ერევანთან | პრაქტიკული overlap |
| --- | --- | --- |
| დასავლეთ ევროპა (CET) | 2-3 საათით უკან | სამუშაო დღის უმეტესი ნაწილი |
| გაერთიანებული სამეფო | 3-4 საათით უკან | ერევნის შუადღე = ლონდონის დილა |
| Gulf (UAE, KSA) | 0-1 საათი | სრული დღის overlap |
| აშშ-ის აღმოსავლეთ სანაპირო | 8-9 საათით უკან | ერევნის საღამო = აშშ-ის დილა |

საათის მიღმა სამი რამ წერილობით დააფიქსირეთ: ვალდებულებად აღებული sync საათები, დოკუმენტაციის ენა artifact-ების ყოველი კლასისთვის (EN სტანდარტია ops docs-ისთვის; RU და HY გავრცელებული სამუშაო ენებია) და დასახელებული ესკალაციის გზა რეაგირების მოლოდინებით. ბუნდოვანი თანამშრომლობის პირობები არის ის ადგილი, სადაც offshore engagement-ები რეალურად ვარდება.

## განაკვეთები და კონტრაქტინგი

მხოლოდ ტიპური საბაზრო დიაპაზონების სახით, არა Dali-ს ან სხვისი კოტირებებით: blended სააგენტო განაკვეთები AI და automation სამუშაოსთვის ერევანში ჩვეულებრივ $25-60 საათში ზოლში ჯდება, შესადარებელი seniority-ის $100-250-ის წინააღმდეგ აშშ-სა და დასავლეთ ევროპაში. განსაჯეთ პირველი წლის სრული ღირებულება - build, retainer, LLM usage თქვენს მოცულობაზე და თქვენივე გუნდის დრო - და არა საათობრივი ეტიკეტი.

ქაღალდზე: სომხური შპს-ები საერთაშორისო კონტრაქტებს რუტინულად აფორმებენ, ინგლისურენოვანი კონტრაქტები ცალსახა IP assignment-ით სტანდარტია, IT სექტორის საგადასახადო სტიმულები კი ისტორიულად ლოკალურ ხარჯების ბაზას უჭერდა მხარს (პირობები იცვლება, ამიტომ მიმდინარე წესები იურისტთან გადაამოწმეთ). თუ GDPR-ის ან მსგავსი რეჟიმების ქვეშ ხართ, შეთანხმდით data location-ზე და ხელი მოაწერეთ DPA-ს, სანამ production მონაცემები გაედინება. სომხეთის EAEU წევრობა ზოგი procurement გუნდისთვის მნიშვნელოვანია; თუ თქვენსას ეს ადარდებს, საკითხი ადრე დააყენეთ.

## Pilot დიზაინი, რომელიც გიცავთ

1. **ჯერ discovery.** მიმდინარე პროცესის წერილობითი workflow რუკა, exceptions-ის ჩათვლით.
2. **Gates პირველივე დღიდან.** შეუქცევადი მოქმედებები - გაგზავნები, გადახდები, ჩანაწერების ცვლილებები - human approval-ს საჭიროებს, სანამ მტკიცებულება მოდუნებას არ გაამართლებს.
3. **Acceptance test-ები.** Pass/fail კრიტერიუმები დასრულებული სამუშაოს ხარისხზე, შეთანხმებული build-ის დაწყებამდე.
4. **Evals და regression შემოწმებები.** რათა მოდელის ან prompt-ის ცვლილებებმა output ჩუმად ვერ დაასუსტოს.
5. **Observability.** Logs და traces, რომლებსაც თქვენი გუნდი ვენდორის ზარზე დასწრების გარეშე კითხულობს.
6. **Handoff პაკეტი.** Docs, runbook, credentials გეგმა, ტრენინგი და განსაზღვრული exit პირობები.

ვენდორი, რომელიც ამ ექვსიდან რომელიმეს ეწინააღმდეგება, გეუბნებათ, როგორი იქნება ცხოვრება გაშვების შემდეგ.

## FAQ

### Remote საერთაშორისო ვენდორები OK არიან?
დიახ, თუ time zone-ები და data წესები თქვენთვის მუშაობს. Agent delivery ბუნებით remote-friendly-ა: discovery ზარები, gated release-ები და ყოველკვირეული demo-ები ოფისში ვიზიტს არ საჭიროებს. ორი რამ, რაზეც გეოგრაფია ნამდვილად მოქმედებს, არის synchronous overlap აქტიური build-ისთვის (მიზნად დაისახეთ ოთხი საათი დღეში) და data იურისდიქცია, რომელსაც DPA-ითა და ცალსახა hosting პირობებით აგვარებთ.

### უნდა ვამჯობინოთ ლოკალური legal entity?
ეს procurement გადაწყვეტილებაა და არა ტექნიკური diligence-ის შემცვლელი. ლოკალურ entity-ს შეუძლია სომეხი მყიდველებისთვის invoicing, ვალუტისა და დავების მოგვარება გაამარტივოს, და ზოგი enterprise მას მოითხოვს. ის ვერაფერს გეუბნებათ იმაზე, უშვებს თუ არა გუნდი gated production სისტემებს, ამიტომ artifact-ების იგივე შემოწმებები ორივე შემთხვევაში ჩაატარეთ.

### რას ახდევინებენ ჩვეულებრივ ერევნული გუნდები agent სამუშაოსთვის?
ტიპური საბაზრო დიაპაზონების სახით: blended განაკვეთები დაახლოებით $25-60 საათში, scoped pilot-ები კი ამ ბაზიდან ფასდება. ბაზრის შიგნით გაბნევა ფართოა, და იაფი ბოლო ხშირად evals-ს, gates-სა და observability-ს გამორიცხავს. შეადარეთ bid-ები იდენტურ scope-ზე ამ პუნქტების ცალსახა დასახელებით, თორემ სხვადასხვა პროდუქტს ადარებთ.

### როგორ გადავამოწმოთ references fake მეტრიკების გარეშე?
References-ს process-ზე ჰკითხეთ და არა შედეგებზე: როგორ მიმდინარეობდა discovery, რა იყო gated, როგორ დამუშავდა პირველი ინციდენტი, რას შეიცავდა handoff. მოგონილი ისტორიები process კითხვების ქვეშ ინგრევა. ამას დაუმატეთ გასუფთავებული artifact-ები ვენდორისგან - redacted gate map მეტს ამტკიცებს, ვიდრე ნებისმიერი პროცენტული განაცხადი.
