## პირდაპირი პასუხი

ელოდეთ ჯერ ფასიან discovery-ს ან audit-ს, შემდეგ fixed-price pilot-ს ერთ workflow-ზე, შემდეგ კი არჩევით monthly retainer-ს, როცა agent უკვე live არის. ტიპური საბაზრო დიაპაზონები 2026-ში: audit-ები დაახლოებით $2,000-15,000, pilot-ები ერთ workflow-ზე $10,000-50,000, ops retainer-ები $1,500-10,000 თვეში. იაფი unlimited 'agents everywhere' პაკეტები ჩვეულებრივ ნიშნავს თხელ demo-ებს gates-ის, logging-ისა და ownership-ის გარეშე.

## სამეტაპიანი კომერციული ფორმა

სანდო agent სააგენტოების უმეტესობა ფასს სამ ეტაპად აწყობს.

1. **Discovery ან audit.** ფასიანი, მოკლე, ფიქსირებული ფასით. შედეგი: workflow-ის რუკა, რისკების სია და pilot-ის შეთავაზება წერილობითი acceptance test-ით.
2. **Fixed-scope pilot.** ერთი workflow, ერთი acceptance test, დასახელებული tools, human gates რისკიან მოქმედებებზე. ფიქსირებული ფასი, ფიქსირებული ვადა.
3. **Ops retainer.** არჩევითი. Monitoring, evals, იტერაცია და მხარდაჭერა agent-ის გაშვების შემდეგ.

ყველაფერი დანარჩენი, რასაც შეხვდებით - hourly consulting, platform license-ები, outcome fee-ები - ამ სამის ვარიაციაა.

| Fixed-price pilot | მკაფიო scope, გაზიარებული რისკი | ზედმეტი მარაგი, როცა brief ბუნდოვანია |
| Monthly retainer | მუდმივი ops და იტერაცია | Standby ბილინგი განსაზღვრული SLA-ს გარეშე |
| Per-agent ან per-seat license | ვენდორის პროგნოზირებადი შემოსავალი | იხდით პლატფორმაში, რომელიც შეიძლება არ გჭირდებათ |
| Outcome ან revenue share | ქაღალდზე გასწორებული სტიმულები | ატრიბუციის დავები, რთული კონტრაქტები |

Build-ისთვის ამჯობინეთ fixed pilot, ხოლო operations-ისთვის - retainer განსაზღვრული scope-ით. ამჯობინეთ იმპლემენტაცია tools-ში, რომლებზეც უკვე იხდით, ახალი platform license-ების ნაცვლად - თუ ახალი tool თავად პროდუქტი არ არის.

## ტიპური საბაზრო დიაპაზონები

ეს ტიპური საბაზრო დიაპაზონებია და არა Dali-ს კოტირებები. ისინი ძლიერ იცვლება რეგიონის, ვენდორის seniority-ისა და იმის მიხედვით, რამდენ integration სამუშაოს მალავს scope. აღიქვით ორიენტირად და არა შეთავაზებად.

Quote, რომელიც ამ დიაპაზონებზე ბევრად დაბალია, ავტომატურად თაღლითობა არ არის. ჩვეულებრივ ეს ნიშნავს, რომ რაღაც აკლია: discovery, gates, logging, დოკუმენტაცია, ან ვინმე on-call გაშვების შემდეგ.

ორიენტირისთვის: თავად Dali-ის პილოტები fixed-scope ფორმატშია - $1,900-$3,500 მიმართულების მიხედვით, გაფართოებული ტიერი $4,000. Scope ფიქსირდება მოკლე აუდიტის შემდეგ, ამიტომ შეთავაზებული ფასი ვალდებულებაა და არა შეფასება. პაკეტური პილოტები ზემოთ მოცემულ ტიპურ custom დიაპაზონებზე იაფია იმიტომ, რომ scope სტანდარტიზებულია, და არა იმიტომ, რომ ნაბიჯები გამოტოვებულია.

## ხარჯების კატეგორიები, რომლებსაც მყიდველები ივიწყებენ

Build მთელი ანგარიში არ არის. ეს პუნქტები პირველივე დღიდან ჩადეთ ბიუჯეტში.

- **LLM call costs.** Agent-ის ყოველი გაშვება ტოკენებს ხარჯავს. იკითხეთ, ვინ იხდის API-ის ანგარიშს, როგორ იზღუდება usage და რა ხდება, როცა retry ციკლი ცუდად იქცევა. მიიღეთ თვიური შეფასება თითო workflow-ზე თქვენს რეალურ მოცულობაზე.
- **Evals-ის მოვლა.** მოდელები იცვლება და prompt-ები დრეიფობს. Eval set-ებს მოვლა სჭირდება, თორემ ხარისხი ჩუმად დეგრადირდება.
- **Monitoring და logging.** ვიღაცამ უნდა წაიკითხოს trace-ები, როცა agent რაღაც უცნაურს აკეთებს.
- **Incident response.** ვინ არის on-call, რა რეაგირების დროით და რა ფასად.
- **Change management.** გუნდის ტრენინგი, runbook-ების განახლება, gates-ის გაფართოება ან შევიწროება ნდობის ზრდასთან ერთად.
- **მხარდაჭერის ფანჯარა გაშვების შემდეგ.** Pilot მხარდაჭერის პერიოდის გარეშე არის demo ინვოისით.

## რა უნდა იყოს pilot quote-ში

Production-grade pilot quote პუნქტობრივად შეიცავს:

- Workflow-ის რუკას ზუსტი ნაბიჯებით scope-ში
- დასახელებულ integrations-ს და ვინ იძლევა წვდომებს
- წერილობით acceptance test-ს: შესასვლელები, მოსალოდნელი შედეგები, გავლის ზღვარი
- Gate-ის წესებს: რომელი მოქმედებები საჭიროებს human approval-ს და ვინ ამტკიცებს
- Logging-ს და სად ცხოვრობს trace-ები
- Handoff პაკეტს: დოკუმენტაცია, runbook, credentials გეგმა
- LLM costs-ის შეფასებას და ვინ იხდის
- მხარდაჭერის ფანჯარას go-live-ის შემდეგ
- ცალსახა exclusions-ს

თუ სამი ან მეტი აკლია, თქვენ წინაშეა demo quote, რომელიც pilot-ად არის გადაცმული.

## დაბალფასიანი სამუშაოს ფარული ხარჯები

Underpriced agent სამუშაო იაფი არ რჩება. ტიპური მომდევნო ანგარიშები:

- Rewrite-ები მას შემდეგ, რაც secrets client-side კოდში ან ლოგებში აღმოჩნდება
- CRM pollution უმეთვალყურეო automation-ისგან, რომელიც ცუდ ჩანაწერებს მასშტაბურად წერს
- არავინ on-call, როცა agent პარასკევს ღამით ცდება
- ცოდნა მიდის contractor-თან ერთად, და ყოველი ცვლილება ნულიდან იწყება
- მეორე ვენდორი, რომელსაც პირველი ვენდორის სისტემის reverse-engineering-ში უხდიან

ერთი არასწორი ავტონომიური მოქმედების ფასი - ცუდი refund batch, არასწორი წერილი კლიენტების სიაზე, გაფუჭებული pipeline - რეგულარულად აჭარბებს სხვაობას იაფ bid-სა და სანდო bid-ს შორის.

## როგორ შევადაროთ quote-ები სამართლიანად

1. **Normalize-ეთ scope.** ყველა quote დააყენეთ ერთი და იმავე workflow-ის, tools-ის, მოცულობისა და acceptance test-ის წინააღმდეგ. თუ ვენდორებმა brief სხვადასხვანაირად გაიგეს, გაასწორეთ brief და თავიდან იკითხეთ.
2. **იკითხეთ, რა ხდება, როცა agent ცდება.** Gates, rollback, ესკალაციის გზა, on-call. ვენდორი პასუხის გარეშე demo-ს აფასებს.
3. **იკითხეთ, ვინ იხდის production hardening-ს.** Logging, evals, security review: ფასის შიგნით თუ change request მოგვიანებით?
4. **შეადარეთ პირველი წლის სრული ღირებულება.** Build-ის ფასი პლუს retainer პლუს LLM usage პლუს თქვენი გუნდის დრო, და არა მხოლოდ pilot-ის ხაზი.
5. **აწონეთ ownership.** ოდნავ უფრო ძვირი ვენდორი, რომელიც სისტემას ადოკუმენტირებს და თქვენს გუნდს ავარჯიშებს, მეექვსე თვისთვის ჩვეულებრივ უფრო იაფი გამოდის.

## FAQ

### უფასო pilot კარგი ნიშანია?
Production სისტემებისთვის იშვიათად. უფასო სამუშაო ჩვეულებრივ გამოტოვებს discovery-ს, acceptance test-ებსა და gates-ს - იმას, რაც agent-ს უსაფრთხოს ხდის. ამაში მოგვიანებით rework-ის სახით გადაიხდით.

### ფასში tools უნდა შედიოდეს?
ამჯობინეთ იმპლემენტაცია tools-ში, რომლებსაც უკვე ფლობთ, თუ ახალი tool თავად პროდუქტი არ არის. Quote, რომელიც platform license-ით იწყება ნებისმიერ discovery-მდე, პლატფორმას ყიდის და არა თქვენს შედეგს.

### როდის არის retainer გამართლებული?
როცა agent-ები live არიან და სჭირდებათ monitoring, evals და იტერაცია. Retainer განსაზღვრული scope-ისა და რეაგირების დროის გარეშე standby ბილინგია.

### ვინ უნდა იხადოს LLM API-ის ანგარიში?
ჩვეულებრივ თქვენ, საკუთარი API key-ებით, ვენდორი კი იძლევა usage-ის შეფასებას და cap-ებს. ვენდორის ხელში მყოფი key-ები ხარჯებს გაუმჭვირვალეს ხდის და ვენდორის შეცვლას ართულებს.

### როგორ დავგეგმო პირველი წლის ბიუჯეტი?
შეკრიბეთ ოთხი ხაზი: audit, pilot, retainer გაშვების შემდგომი თვეებისთვის და LLM usage რეალურ მოცულობაზე. ზემოთ მოცემული ტიპური საბაზრო დიაპაზონები საწყის კონვერტს იძლევა; თქვენი integrations და რისკის პროფილი მას ზემოთ ან ქვემოთ სწევს.
