## პირდაპირი პასუხი

შეადარეთ AI agent სააგენტოები საერთო, წერილობითი scorecard-ით: discovery-ის ხარისხი, gate დიზაინი, security posture, pilot-ის საზღვარი, კომერციული სიცხადე და ownership-ის გადაცემა. გაუგზავნეთ ყველა კანდიდატს ერთი და იგივე brief, მოითხოვეთ წერილობითი pilot გეგმა acceptance test-ით და დააქულეთ გეგმები ერთმანეთის წინააღმდეგ და არა sales deck-ები. იგნორირეთ vanity awards და ლოგოების კედლები; ისინი მარკეტინგის ბიუჯეტებს პროგნოზირებენ და არა production შედეგებს.

## რატომ მარცხდება შედარებების უმეტესობა

მყიდველები ჩვეულებრივ არასწორ არტეფაქტებს ადარებენ: სამ sales deck-ს გვერდიგვერდ, deck-ები კი ისეა ოპტიმიზებული, რომ ერთმანეთს ჰგავდეს. განსხვავებები, რომლებსაც მნიშვნელობა აქვს - ვინ აპროექტებს approval gates-ს, ვინ წერს acceptance test-ს, რა ხდება, როცა agent ღამის 2 საათზე ცდება - სლაიდზე არასოდეს ჩნდება.

ამის ნაცვლად შეადარეთ წერილობითი pilot გეგმები. Pilot გეგმა თითოეულ სააგენტოს აიძულებს, ქაღალდზე დააფიქსიროს scope, gates, მეტრიკები და exclusions; ძლიერი ვენდორები ისეთ გეგმებს აწარმოებენ, რომ სხვა გუნდსაც რომ გადასცეთ, სისტემა მაინც აშენდება.

## Scorecard

დააქულეთ თითოეული სააგენტო 1-5 ყოველ განზომილებაზე. გამოიყენეთ წონები საწყის წერტილად და მოარგეთ თქვენს რისკის პროფილს.

| განზომილება | წონა | როგორ გამოიყურება 5 | როგორ გამოიყურება 1 |
| --- | --- | --- | --- |
| Discovery-ის ხარისხი | 20% | Quote-მდე ეკითხება მოცულობებზე, exceptions-სა და შეცდომის ფასზე | Quote-ს იძლევა ერთსტრიქონიანი brief-იდან |
| Gate დიზაინი | 20% | ასახელებს, რომელი მოქმედებები საჭიროებს human approval-ს და ვინ ამტკიცებს | "Agent სრულად ავტონომიურია" |
| Security posture | 15% | კონკრეტული პასუხები secrets-ზე, PII handling-სა და წვდომების scoping-ზე | "Security-ს სერიოზულად ვეკიდებით" |
| Pilot-ის საზღვარი | 15% | ერთი workflow, წერილობითი acceptance test, ცალსახა exclusions | "Phase 1", რომელიც ხუთ სისტემას ეხება |
| კომერციული სიცხადე | 10% | ფიქსირებული pilot ფასი, პუნქტობრივი retainer, LLM cost შეფასება | ღია hourly, tools ბუნდოვნად ბილინგდება |
| Ownership-ის გადაცემა | 15% | Docs, runbook, credentials გეგმა, ტრენინგი საბაზისო ფასში | Handoff იყიდება როგორც მომავალი change request |
| Delivery გუნდი | 5% | ხვდებით ადამიანებს, რომლებიც რეალურად ააშენებენ | ხვდებით მხოლოდ closer-ს |

დააქულეთ წერილობითი მტკიცებულებიდან და არა იმით, როგორი შეგრძნება დატოვა ზარმა, და შეზღუდეთ ფასის წონა: იაფი bid, რომელიც gates-სა და security-ზე 1-ს იღებს, მაგიდაზე ყველაზე ძვირი ვარიანტია, როგორც ამას [red flag-ების სია](/ge/blog/red-flags-when-hiring-ai-agent-company) დეტალურად შლის.

## როგორ გავუშვათ bake-off

1. **დაწერეთ ერთი brief და გაყინეთ.** ერთი workflow, რეალური მოცულობები, ჩართული tools და არასწორი მოქმედების ფასი. ყველა ვენდორი იდენტურ დოკუმენტს იღებს.
2. **მოითხოვეთ წერილობითი pilot გეგმა და არა proposal deck.** სავალდებულოა: scope, acceptance test გავლის ზღვრით, gate-ის წესები, logging გეგმა, LLM cost შეფასება, მხარდაჭერის ფანჯარა და exclusions.
3. **გადაიხადეთ discovery-ში, როცა workflow არეულია.** მოკლე ფასიანი discovery თქვენი ორი საუკეთესო კანდიდატისგან სამ უფასო ვარაუდს სჯობს, და discovery-ის შედეგი თავად არის audition.
4. **დაკითხეთ acceptance test.** ჰკითხეთ თითოეულ ვენდორს: რა შესასვლელები, რა მოსალოდნელი შედეგები, რა pass rate, ვინ უშვებს და რა ხდება ჩავარდნისას. ვენდორები, რომლებიც აქ იმპროვიზირებენ, production-შიც იიმპროვიზირებენ.
5. **დასვით ინციდენტის კითხვა.** "Agent პარასკევს ღამით 200 კლიენტს არასწორ წერილს უგზავნის. გამატარეთ მომდევნო საათზე." დააქულეთ კონკრეტულობა: rollback, ესკალაციის გზა, on-call, postmortem.
6. **შეამოწმეთ evals და observability.** ჰკითხეთ, როგორ ტესტავენ prompt ცვლილებებს rollout-მდე, სად ცხოვრობს trace-ები და როგორ ამჩნევენ ხარისხის დრეიფს მოდელის განახლების შემდეგ. სააგენტოები eval ჩვევის გარეშე რეგრესიებს ჩუმად უშვებენ production-ში.

## Quote-ების ნორმალიზება შედარებამდე

Quote-ები მხოლოდ მაშინ არის შესადარებელი, როცა scope იდენტურია. კომერციული სიცხადის დაქულებამდე ნორმალიზეთ:

- იგივე workflow, იგივე tools, იგივე მოცულობის დაშვებები
- იგივე acceptance test მიმაგრებული ყველა quote-ზე
- LLM usage შეფასებული თქვენს რეალურ მოცულობაზე, საკუთარ ხაზად, მკაფიო პასუხით, ვინ ფლობს API key-ებს
- მხარდაჭერის ფანჯარა და retainer-ის scope ცხადად წერია და არა იგულისხმება
- Exclusions ჩამოთვლილია ცალსახად

შემდეგ შეადარეთ პირველი წლის სრული ღირებულება: pilot პლუს retainer-ის თვეები პლუს LLM usage პლუს თქვენი გუნდის დრო. Pilot, რომელიც 30%-ით იაფი ჩანს, ხშირად ძვირი ხდება, როგორც კი hardening, handoff და მხარდაჭერა change request-ებად ბრუნდება.

## წონები თქვენი სიტუაციისთვის

Default წონები ვარაუდობს production სისტემას, რომელიც კლიენტებს ან ფულს ეხება. მოარგეთ გააზრებულად:

- **მაღალი რისკის მოქმედებები (refunds, outbound email, ჩანაწერები მასშტაბით):** გაზარდეთ gate დიზაინი და security ჯამური წონის ნახევრამდე.
- **შიდა technical owner არ არის:** გაზარდეთ ownership-ის გადაცემა; სისტემა, რომელსაც ვერავინ მართავს, ვალდებულებაა subscription-ით.
- **შიდა drafting tool, დაბალი blast radius:** ოდნავ შეარბილეთ gates და მეტი წონა მიეცით სისწრაფესა და ფასს.
- **რეგულირებადი მონაცემები:** security ხდება pass-fail ფილტრი დაქულების დაწყებამდე და არა შეწონილი განზომილება.

## შედარების გავრცელებული ხაფანგები

- **ქიმიის დაქულება კომპეტენციად.** სასიამოვნო ზარი gate მოდელი არ არის.
- **მეტრიკის განსაზღვრის ვენდორისთვის მინდობა.** "Engagement" და "sessions" ვენდორისთვის მოსახერხებელი ციფრებია. მოითხოვეთ cycle time, error rate და override rate.
- **ერთი workflow-ის ვენდორებზე გაყოფა დაზღვევის მიზნით.** მიიღებთ ორ ნახევარსისტემას და integration ნაკერს, რომელსაც არავინ ფლობს. აირჩიეთ ერთი პარტნიორი პირველი pilot-ისთვის.
- **ყველაზე დიდი გუნდის ყველაზე უსაფრთხოდ მიჩნევა.** ჰკითხეთ, ზუსტად ვინ იმუშავებს თქვენს სისტემაზე; senior წყვილი ხშირად აჯობებს მბრუნავ bench-ს.

თითოეული განზომილების უკან მდგარი ღრმა კრიტერიუმებისთვის იხილეთ [როგორ შევაფასოთ საუკეთესო AI agent სააგენტოები](/ge/blog/best-ai-agent-agencies-how-to-evaluate).

## FAQ

### ფასი score-ის 50% უნდა იყოს?

არა. შეზღუდეთ ფასი ჯამური წონის დაახლოებით 10-15%-ზე. Underpriced agent სამუშაო არის ადგილი, სადაც gates, logging და handoff ჩუმად ქრება, და ერთი არასწორი ავტონომიური მოქმედების მომდევნო ანგარიში რეგულარულად აჭარბებს სხვაობას იაფ bid-სა და სანდო bid-ს შორის. ამის ნაცვლად შეადარეთ პირველი წლის სრული ღირებულება და არა მხოლოდ pilot-ის ფასი.

### რა ვქნათ, თუ ქულები ტოლია?

გაარღვიეთ ტოლობა ownership-ის გადაცემით და რეალურ workflow owner-თან ქიმიით, ამ თანმიმდევრობით. ვენდორი, რომელიც სისტემას ადოკუმენტირებს და თქვენს გუნდს ავარჯიშებს, მეექვსე თვისთვის უფრო იაფია იმავე ფასადაც კი. თუ მაინც ტოლია, გაუშვით მოკლე ფასიანი discovery ორივესთან და შეადარეთ შედეგები.

### რამდენი სააგენტო უნდა იყოს შედარებაში?

სამიდან ხუთამდე brief-ის ეტაპზე, ორი ფასიანი discovery-ის ეტაპზე. სამზე ნაკლები კალიბრაციას არ გაძლევთ; ხუთზე მეტი ნიშნავს, რომ თქვენი brief ზედმეტად იაფი იყო პასუხის გასაცემად და შაბლონურ პასუხებს მიიღებთ.

### შეიძლება scorecard გამოვტოვო პატარა pilot-ისთვის?

შეამცირეთ და ნუ გამოტოვებთ. დაიტოვეთ სამი კითხვა, რომლებიც შედეგებს პროგნოზირებს: რა არის acceptance test, რომელი მოქმედებები საჭიროებს human approval-ს და რას ვფლობთ handoff-ზე. ვენდორი, რომელიც ამათ წერილობით ვერ პასუხობს, demo-ს გაფასებთ.

### უნდა შევწონო ინდუსტრიული გამოცდილება ჩემს vertical-ში?

მსუბუქად. Workflow-ის მექანიკა ინდუსტრიებს შორის გადადის, gate დისციპლინა კი მხოლოდ იმიტომ არ ჩნდება, რომ ვენდორმა თქვენი ჟარგონი იცის. დააქულეთ vertical გამოცდილება ბონუს ქულად და გადაამოწმეთ process კითხვებით და არა ლოგოებით.
